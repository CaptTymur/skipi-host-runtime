# AGENTS.md — generic-модуль (максимальная строгость)

**Твои изменения влияют на ВСЕ дома** (Seafarer, Crewing, Broker, On Board, Ship Management). Чем меньше радиус поражения — тем длиннее поводок; здесь радиус максимальный, поводок самый короткий.

## Правила модуля

- **`make verify-all` (skipi-verify) обязателен перед завершением любой задачи.** Красный прогон = задача не завершена.
- **Публичный API заморожен — add-only.** Менять, удалять или переименовывать существующие экспорты — только с явного разрешения человека (запрос через handoff в штаб).
- Дифф модуля = shared: получает второе LLM-ревью до мерджа. До появления CI второе ревью запрашивается через handoff в штаб; после — job.
- **Твой коммит НЕ попадает в дома сам.** Package-manager-доставки нет: модуль доезжает до дома только руками — копирование байтов в `<дом>/dist` (или inline), commit в git дома, обновление vendor-пина (semver+SHA stamp). Это отдельная задача доставки, не часть правки модуля. Механизм: PROJECT_STATE §5 в skipi-ops.

## Общий протокол (одинаков во всех репо Skipi)

- Одна задача = один worktree = одна сессия. Задача закрыта — сессия закрывается; новая задача = свежая сессия.
- Минимальный дифф: меняй только то, что требует задача.
- Bugfix = сначала failing-test, воспроизводящий баг → фикс → зелёный прогон. Фикс без failing-test'а не принимается.
- После работы: commit + push.
- `--no-verify` запрещён.
- systemd, деплой, прод-сервер и флот ботов — вне скоупа; нужно — handoff в штаб (`skipi-ops/handoffs/`).
- Инцидент (регрессия, потеря данных) → SKI-INC-NNN в `skipi-ops/incidents/`.
- Сессия запускается из папки этого репо (`cd <репо> && claude`), не из корня. Если этого файла нет в списке `/memory` — сессия поднята неправильно: остановись и сообщи человеку.
- Обмен с другими агентами — через артефакты на диске (коммиты, handoffs, verify-отчёты), не копипастом между окнами.
